# Two-minute demo

1. **Problem (20s):** Students receive convincing fake funding offers and urgent account messages. They need understandable warning signs before responding.
2. **High-risk example (35s):** Click the fictional bursary example. Check it. Show the sensitive-data request, payment lure and institutional domain mismatch. Explain that no link was opened.
3. **Ordinary message (20s):** Load the study-group example. Show Low risk and the explicit limitation: few known signals is not verified safety.
4. **Privacy (20s):** Local mode keeps the message in this browser. No sign-in or saved scan history. If AI is enabled, it requires consent; the model sees findings and can explain them, but cannot change the verdict.
5. **Feasibility and next steps (25s):** React/Vite frontend, separate static frontend hosting, optional Supabase Edge Function, synthetic tests. Next: larger independently reviewed examples, student feedback and stronger cloud abuse protection before public scaling.

## Honest capability statement

The current working demo uses rules. The AI endpoint is implemented but becomes a live capability only after account configuration, deployment and end-to-end verification. Twelve synthetic cases are development checks, not an accuracy benchmark. The product does not prove that a sender or link is legitimate.
